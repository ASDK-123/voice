## 3. P0 问题（需立即修复）

### P0-1 启动 API 时可能触发属性错误（与 v2 worker 不兼容）

- 证据：
- `ui/api_page.py:469`
- `ui/api_page.py:470`
- `core/worker.py:544`
- `core/worker.py:574`
- 现象：
- 代码直接访问 `self.main_window.current_worker.cosyvoice`。
- 但 `V2AudioGenerationWorker` 没有 `cosyvoice` 属性。
- 影响：
- 在 `cosyvoice_model is None` 且当前任务 worker 为 v2 时，点击“启动 API 服务”可能抛 `AttributeError`，导致启动流程中断。
- 建议修复：
- 用 `getattr(self.main_window.current_worker, "cosyvoice", None)` 或 `hasattr` 防御式访问。
- 最好统一为 `main_window` 内部提供 `get_active_model()`，避免页面直接猜测 worker 类型。

## 4. P1 问题（本迭代建议完成）

### P1-1 桥接服务启动/停止在 UI 主线程阻塞

- 证据：
- `ui/api_page.py:888`（`time.sleep(1.0)`）
- `ui/api_page.py:951`（`wait(timeout=5)`）
- `ui/main_window.py:508`（主线程 `requests.get(..., timeout=0.5)`）
- 影响：
- 点击按钮时界面可能短暂卡顿，慢机或网络异常时体感明显。
- 建议修复：
- 启停桥接改为后台线程 + 信号回主线程更新 UI。
- 健康探测放入已有 worker，不在主线程直接请求。

### P1-2 桥接进程管道使用 `PIPE` 但未持续消费，存在阻塞风险

- 证据：
- `ui/api_page.py:881`
- `ui/api_page.py:882`
- 现象：
- `stdout/stderr` 都接到 `PIPE`，仅失败时读一次 `stderr`，正常运行期间不消费。
- 影响：
- 若桥接进程日志输出较多，管道缓冲区可能写满，子进程被阻塞。
- 建议修复：
- 方案 A：若不需要捕获日志，改为 `stdout=None, stderr=None`。
- 方案 B：单独日志读取线程持续消费并转发 UI 日志。

### P1-3 API Key 环境变量只设不清，可能残留旧鉴权状态

- 证据：
- `ui/api_page.py:530`
- `ui/api_page.py:531`
- 现象：
- 仅在 key 非空时设置 `V2_API_KEY`，但 key 清空后没有 `pop`。
- 影响：
- 用户在设置页清空 key 后，服务仍可能沿用旧 key，出现“明明清空了还鉴权失败/需要 key”的错觉。
- 建议修复：
- 当 `ui_api_key` 为空时执行 `os.environ.pop("V2_API_KEY", None)`。

### P1-4 `voice_settings` 的 worker 清理未绑定 `finished`，有线程生命周期竞态

- 证据：
- `ui/voice_settings.py:71`
- `ui/voice_settings.py:73`
- `ui/voice_settings.py:380`
- `ui/voice_settings.py:390`
- 现象：
- `_run_api_task` 在 `ok/err` 回调里立即 `_cleanup()` + `deleteLater()`，而不是在 `finished` 后清理。
- 影响：
- 高并发或窗口快速关闭时，可能出现偶发 `QThread` 生命周期竞态（间歇性 warning/不稳定行为）。
- 建议修复：
- 与 `voice_setup_wizard` / `emotion_assets_panel` 一致：`w.finished.connect(_cleanup)`，回调里不直接删线程对象。

### P1-5 深色主题一致性不足（当前 token 是固定浅色）

- 证据：
- `ui/main_window.py:65`
- `ui/main_window.py:69`
- `ui/theme/tokens.py:22`
- `ui/theme/tokens.py:35`
- `ui/components/voice_refs_sheet.py:65`
- `ui/voice_settings.py:531`
- `ui/voice_settings.py:535`
- `ui/components/emotion_assets_panel.py:421`
- `ui/components/emotion_assets_panel.py:425`
- 现象：
- 主窗口支持 Light/Dark/AUTO，但 token 和局部 QSS 仍有固定浅色值（`#FFFFFF/#FAFBFC/#EFF6FF`）。
- 影响：
- 深色主题下对比度与视觉一致性下降，局部区域可能“发白”突兀。
- 建议修复：
- 建立按主题切换的 token（light/dark 两套），禁止页面内硬编码颜色。

## 5. P2 问题（可并行治理）

### P2-1 异常吞噬较多，排障成本高

- 证据：
- `ui/settings.py:211`
- `ui/task_plan.py:617`
- `ui/api_page.py:715`
- 统计：
- `except Exception`：226 处。
- `bare except`：3 处。
- 影响：
- 线上问题可能被静默吞掉，用户只看到“无响应/无提示”。
- 建议修复：
- 至少在 `except` 中记录日志（含上下文），对用户关键路径给出可见反馈。

### P2-2 Lint 负债较高，增加维护噪音

- 证据（`ruff check ui --statistics`）：
- `F401` unused-import：36
- `E741` ambiguous-variable-name：8
- `E722` bare-except：3
- `F541` 无占位 f-string：2
- `F841` unused-variable：1
- 影响：
- 无法快速识别新增问题，review 噪音高。
- 建议修复：
- 先自动修复可修复项（`ruff --fix`），再手动清理剩余项。

### P2-3 超大单文件影响可维护性

- 证据：
- `ui/voice_settings.py`（2266 行）
- `ui/emotion_voices.py`（1251 行）
- `ui/components/emotion_assets_panel.py`（947 行）
- `ui/api_page.py`（931 行）
- 影响：
- 回归风险高、理解成本高、多人协作冲突多。
- 建议修复：
- 以“页面壳 + 子组件 + service/adapter + state”分层拆分，优先拆 `voice_settings.py`。
