# CosyVoice Desktop 语音设置页大改版设计方案（Apple 风格）

日期：2026-02-15  
状态：设计方案（仅文档，不改代码）  
适用范围：`ui/voice_settings.py`、`ui/components/voice_refs_sheet.py`、`ui/components/emotion_assets_panel.py`（必要时含 `ui/v2_client.py`、`core/api_v2_routes.py` 小幅配合）

## 1. 背景与目标

你反馈的问题不是单点 bug，而是“信息架构 + 编辑模型 + 交互安全 + 反馈链路”整体失衡：

1. 鼠标/焦点稍有误操作就可能改坏文本，删除路径太近且成本低。  
2. `角色#情绪` 的 voice 名称是关键主键，却被当作普通文本自由编辑。  
3. 右侧扩展面板（参考音频）打开方式和布局体验差，主工作区被挤压。  
4. `导入旧配置到 v2` 在当前流程中价值低，常态曝光干扰主任务。  
5. 参考音频试听链路不稳，缺少清晰状态与故障引导。  

本方案目标：

1. 把语音设置页重构为“安全编辑、结构清晰、反馈即时”的专业工具界面。  
2. 统一 voice 主键语义，降低误改和数据污染。  
3. 明确参考音频的主流程（上传、绑定、试听、设主参考、检索）并提升可用性。  
4. 视觉和交互风格遵循 Apple 设计理念（Clarity / Deference / Depth）。

## 2. 现状问题诊断（基于当前实现）

## 2.1 误删/误改风险过高（P0）

现状证据：

1. 表格每行多个 `LineEdit` 默认可编辑，输入即落数据（`textChanged` 直连更新）。  
2. 任意子控件右键菜单都暴露“删除配置”（`on_child_context_menu -> delete_config`）。  
3. 删除操作无二次确认、无撤销。  

体验后果：

1. 误点右键或误触键盘即可改坏配置。  
2. 用户不敢快速操作，效率和信任感都下降。

## 2.2 关键 ID 可随意改写（P0）

现状证据：

1. 名称列直接编辑 `name`。  
2. 只在保存阶段做“补 `#default`”级别规范化（`_normalize_voice_name`），没有强约束与前置校验。  

体验后果：

1. `voice_id` 被误改后可能导致绑定关系错位、查询命中异常。  
2. 用户不清楚哪些字段能改、哪些是系统主键。

## 2.3 右侧扩展框体验差（P1）

现状证据：

1. 右侧面板以固定宽度展开（约 520），主区被硬挤压。  
2. 展开/收起缺少平滑过渡和状态记忆。  
3. 关键操作分散：主表、右侧面板、更多菜单之间跳转成本高。  

体验后果：

1. 视线频繁跳转，操作上下文割裂。  
2. 小屏下主表可读性显著下降。

## 2.4 无效/低价值入口占据主操作区（P1）

现状证据：

1. 底部主按钮区长期显示“导入旧配置到 v2”。  
2. 当前项目主链路已是 v2，迁移属于低频一次性任务。  

体验后果：

1. 主按钮带认知噪音，降低核心路径（管理/应用/试听）聚焦度。  
2. 新用户容易误解成“日常必点步骤”。

## 2.5 参考音频试听链路不可靠（P1）

现状证据：

1. 试听依赖“先选中资源再点击试听”，缺少行内就地播放。  
2. 失败时缺少可执行的恢复指引（例如路径缺失、格式不支持、后端不可达）。  
3. 下载临时文件后播放流程可观测性弱（无进度/状态/重试路径）。  

体验后果：

1. 用户感知为“不能试听”或“偶尔能播偶尔不行”。  
2. 无法快速比对不同参考音频质量。

## 3. 设计原则（Apple 风格落地版）

1. 清晰（Clarity）：把“看”“改”“删”分离，默认只读，编辑需显式进入。  
2. 内容优先（Deference）：界面减少次要按钮，突出角色、情绪、参考池状态。  
3. 层级（Depth）：主列表负责浏览，右侧检查器负责细节，不在一个平面塞完所有动作。  
4. 一致（Consistency）：`character + emotion -> voice_id` 规则统一，不允许隐式漂移。  
5. 宽容（Forgiving）：高风险操作必须确认 + 可撤销。

## 4. 新信息架构（IA）

重构为三栏工作台（Desktop 首选）：

1. 左栏（角色导航，240px）：
- 搜索角色
- 角色分组（含 voice 数量）
- “全部角色 / 最近编辑”切换

2. 中栏（voice 列表，主工作区）：
- 只展示当前角色下情绪行
- 行结构：`emotion`、`mode`、`主参考状态`、`备注摘要`、`最后更新`
- 行内快速动作：试听、绑定、更多

3. 右栏（Inspector，360-560px，可调）：
- Voice 概览卡（只读 ID、角色、情绪）
- 参考音频库（上传/筛选/绑定/设主参考/试听）
- 元数据编辑（备注、语言）
- 风险操作区（解绑、删除）

补充：

1. 顶部保留轻量状态条：当前 v2 配置路径、参考池计数、主参考健康状态。  
2. 底部只保留主任务按钮：`添加` `保存` `应用` `预编译`。迁移入口移出主区。

## 5. 关键交互重构（逐条对应你的问题）

## 5.1 防误删/防误改（解决“鼠标到哪都能删/改”）

改造策略：

1. 引入双模式：`浏览模式`（默认）与 `编辑模式`（显式进入）。  
2. 浏览模式下文本不可直接编辑；点击只选中，不改值。  
3. 高风险动作（删除配置、删除资源）必须二次确认：
- 弹窗明确对象名
- 支持 8 秒撤销（InfoBar `撤销` 按钮）
4. 右键菜单默认只保留非破坏动作（复制、打开位置）；删除移到“更多”并二次确认。  
5. 为表格增加 `Ctrl+Z / Ctrl+Shift+Z` 本地撤销栈。

预期效果：

1. 误操作概率显著下降。  
2. 即使误删也可快速恢复。

## 5.2 voice 名称规则重构（解决“格式不能随便改”）

改造策略：

1. 名称列拆成语义字段：
- `character`（可编辑）
- `emotion`（可选/可输入但受校验）
- `voice_id`（只读预览，自动生成）
2. 规则：`voice_id = {character}#{emotion}`，`emotion` 空值自动 `default`。  
3. 保存前前置校验：
- `character` 不能为空
- 禁止前后空白
- 禁止非法字符（可配置）
4. 系统提供“重命名向导”处理批量改名，并提示引用影响。

预期效果：

1. 主键语义稳定，可编辑但不失控。  
2. 用户知道自己在改“业务字段”还是“系统标识”。

## 5.3 右侧扩展框改造（解决“体验非常差”）

改造策略：

1. 从“弹出式侧边 sheet”升级为“常驻可折叠 Inspector”。  
2. 支持拖拽调宽、双击分割线折叠、记忆上次宽度。  
3. Inspector 标题区固定展示当前上下文：`角色 / 情绪 / voice_id`。  
4. 操作分段：
- `参考池`（主）
- `上传`（次）
- `元数据`（次）
- `危险操作`（末尾）
5. 小屏降级：切换为抽屉覆盖模式（不挤压主表）。

预期效果：

1. 工作流更连贯，视觉负担下降。  
2. 主表信息密度与可读性提升。

## 5.4 旧导入入口治理（解决“导入旧配置选项没用了”）

改造策略：

1. 将“导入旧配置到 v2”从主按钮区移除。  
2. 放入 `工具 > 迁移助手` 二级入口。  
3. 仅在检测到旧配置文件存在时显示提醒卡。  
4. 迁移后记录完成状态，默认不再提醒。

预期效果：

1. 主界面聚焦日常任务。  
2. 迁移功能保留但不打扰。

## 5.5 参考音频试听重构（解决“无法试听”）

改造策略：

1. 资产表每行增加行内播放按钮（无需先选中再点顶部试听）。  
2. 播放状态可视化：`加载中 / 播放中 / 失败`。  
3. 失败提示改为可执行建议：
- 路径丢失 -> “重新下载到本地”
- 格式不支持 -> “转码后重传”
- 服务不可达 -> “检查 API host/port”
4. 预览链路增强：
- 优先本地 path
- 本地缺失时下载到缓存并保留原扩展名
- 缓存命中复用，减少重复下载
5. 提供“在文件夹中打开”与“复制 asset_id”并列入口，便于排障。

预期效果：

1. 试听行为稳定可预期。  
2. 失败可快速定位与恢复。

## 6. 视觉规范（Apple 审美方向）

## 6.1 设计令牌（建议）

1. 字体：`SF Pro Text / PingFang SC / Segoe UI`，按平台回退。  
2. 圆角：容器 12，控件 10，胶囊标签 8。  
3. 间距：8pt 基线（8/12/16/20/24）。  
4. 色彩：中性灰阶为主，品牌色只用于主 CTA 与焦点。  
5. 阴影：低对比轻阴影（避免悬浮感过强）。

## 6.2 组件风格

1. 表格行 hover 轻高亮，不做重边框闪烁。  
2. 选中态使用浅色底 + 左侧细强调条。  
3. 状态芯片统一：
- `主参考可用`（绿色）
- `缺失`（橙/红）
- `未绑定`（灰）
4. 按钮层级：
- 主按钮：实色
- 次按钮：描边/浅底
- 危险按钮：仅在危险区出现

## 7. 模块级改造清单（不改后端协议优先）

## 7.1 `ui/voice_settings.py`

1. 表格编辑模型从“全时可编辑”改为“显式编辑模式”。  
2. 新增 `voice_id` 只读显示逻辑，拆分 `character/emotion` 输入。  
3. 删除改为确认 + 撤销。  
4. 主按钮区移除旧迁移按钮，迁移入口移到工具菜单。  
5. `QSplitter` 行为升级：记忆宽度、平滑展开、窄屏覆盖。

## 7.2 `ui/components/voice_refs_sheet.py`

1. 从临时 sheet 行为改为 Inspector 容器行为。  
2. 支持状态记忆（开关、宽度、最后 tab）。  
3. 顶部上下文与关闭逻辑统一。

## 7.3 `ui/components/emotion_assets_panel.py`

1. 资产表加入行内试听、状态图标、主参考标记。  
2. 上传区与筛选区分组，减少一行塞满控件。  
3. 失败提示增强并带操作建议。  
4. 增加批量绑定/解绑的清晰反馈。

## 7.4 `ui/v2_client.py`（可选增强）

1. 预览下载接口增加文件后缀识别信息（若后端可提供）。  
2. 错误对象中保留更明确的 endpoint 与 request_id，便于 UI 展示。

## 7.5 `core/api_v2_routes.py`（可选增强）

1. `/assets/audio/<id>/content` 返回正确 `Content-Type`（按文件扩展推断），避免播放器识别歧义。  
2. 错误返回补充 `code/details`，支持前端做“可执行错误提示”。

## 8. 分期实施计划

## Phase 1（1 周）- 安全与可用性止血

1. 编辑模式开关 + 删除确认 + 撤销。  
2. 迁移入口移出主按钮区。  
3. 试听失败提示增强。  

交付标准：误删率显著下降，主流程不再被迁移按钮干扰。

## Phase 2（1-2 周）- 信息架构重构

1. 三栏布局与 Inspector 交互落地。  
2. `character/emotion/voice_id` 语义拆分。  
3. 行内主参考状态与快速动作完善。  

交付标准：角色管理与参考音频管理路径连贯。

## Phase 3（1 周）- 稳定性与细节

1. 试听缓存、格式兼容、错误引导闭环。  
2. 视觉打磨与快捷键/可访问性完善。  

交付标准：参考音频试听成功率和定位效率明显提升。

## 9. 验收清单（手工）

1. 浏览模式下不能直接改坏名称/文本。  
2. 删除任意 voice 时出现确认，且可撤销。  
3. `voice_id` 不可自由手写破坏，只能由角色+情绪生成。  
4. 右侧 Inspector 可调宽、可折叠、状态可记忆。  
5. 主界面不再常驻显示“导入旧配置到 v2”。  
6. 参考音频可行内试听；失败时提示可执行修复动作。  
7. 上传后资产可立即出现在当前上下文并支持绑定/设主参考。  
8. 窄屏下不会出现主区被严重挤压不可用。

## 10. 风险与缓释

1. 风险：重构跨度大，短期开发成本增加。  
缓释：按 Phase 分段上线，先做安全止血。

2. 风险：历史用户习惯“直接编辑名称”。  
缓释：提供“高级编辑”入口，但默认收起并给风险提示。

3. 风险：试听兼容性受系统解码器影响。  
缓释：增加本地转码兜底或统一转存 wav 预览策略。

## 11. 本方案如何解决你提出的具体问题

1. “鼠标移动到哪里就能删文字”  
-> 通过默认只读 + 显式编辑 + 撤销机制，彻底降低误改成本。

2. “音色名称格式不能随便更改很不合理”  
-> 改为语义化字段编辑，`voice_id` 自动生成且受规则保护，不再裸改主键。

3. “右边拓展框体验非常差”  
-> 改为可调宽 Inspector，支持状态记忆和窄屏降级，不再强挤主区。

4. “导入旧配置没用了”  
-> 主界面移除，迁移助手化，按需触发。

5. “参考音频不能试听”  
-> 行内试听 + 明确状态 + 可执行错误提示 + 缓存/格式兼容增强。
