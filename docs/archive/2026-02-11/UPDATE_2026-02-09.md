## 1. 本次做了哪些事情

### 1.1 结果音频磁盘缓存（跨 API/桌面端复用）
- 新增磁盘 LRU 缓存目录：`data/cache/`
- 默认容量上限：500MB（可用环境变量 `CACHE_MAX_MB` 调整）
- 缓存内容：推理结果 WAV（按“请求指纹”命名存储）
- 命中策略：同一输入（包含影响输出的全部参数）直接返回缓存音频，达到“秒级响应”
- 并发去重：同一个请求 key 正在生成时，其他请求可等待或改走异步 job（in-flight de-dup）

落地文件：
- `core/cache_manager.py`：磁盘缓存、`index.json`、LRU 淘汰、原子写入、in-flight 去重
- `core/cache_keys.py`：文本归一化、稳定 hash、model/voice/request 指纹计算
- `core/api.py`：v2 synth 全链路接入缓存；job 生成链路也接入缓存
- `core/worker.py`：桌面端生成线程同样写入/读取 `data/cache`（与 API v2 共用）

### 1.2 v2 Jobs 队列与 worker（统一后台调度）
- 将 `/api/v2/jobs` 从“每个 job 起线程”改为“统一后台 worker + PriorityQueue”
- 支持 job 优先级（payload 里的 `priority`，默认 100）
- job 的每个 segment 在执行前先查缓存，命中直接复用，未命中才推理并写回缓存

落地文件：
- `core/api.py`：`V2_JOB_QUEUE`、`_v2_enqueue_job()`、worker loop、`_v2_run_job()` 改造

### 1.3 情绪音色：按“角色分组 + 情绪标签”管理，多参考音频随机化
- voice 命名约定：`角色#情绪`（例如 `Tom#happy`）
- synth 时可传：`character=Tom` + `emotion=happy`，自动解析为对应 voice；若找不到则回退到 `Tom#default`
- 一个情绪 voice 可绑定多个参考音频：`ref_asset_ids=[...]`
- 同一情绪下多参考音频选择策略：
  - 默认 `random_per_text`：对同一文本稳定选择（便于缓存稳定命中）
  - 支持 `fixed`、`random_per_request`（会降低缓存稳定性，不建议默认用）
- 当 `use_instruction=true` 且 `instruction` 存在时：指令作为增强（同时纳入缓存 key）

落地文件：
- `core/emotion_selector.py`：`角色#情绪`、fallback、ref 选择策略（稳定随机）
- `core/api.py`：v2 synth 解析 character/emotion、选择 ref、把选择结果纳入缓存 key

### 1.4 新增健康检查与指标（便于排障/观察）
- 新增：
  - `GET /health`（等价于 v2 health）
  - `GET /metrics`（等价于 v2 metrics）
  - `GET /api/v2/metrics`
- metrics 目前包含：cache hit/miss、hit rate、队列深度、cache 占用、jobs 统计等

落地文件：
- `core/api.py`

### 1.5 情绪管理 UI：网页控制台 + PyQt 桌面端（v2）
目标：让你不用写代码，也能在局域网/本机完成“参考音频资产上传 + 情绪标签 + voice 绑定 ref_asset_ids + 按角色分组查看”，并且桌面端也能闭环管理（不再依赖网页控制台）。

已落地（网页控制台）：
- Assets 上传增加字段：`character` / `emotion` / `language` / `note`
- Voice 编辑增加字段：`character` / `emotion` / `selection_policy` / `ref_asset_ids`
- Ref Picker：按 `character+emotion` 过滤 ref 资产，勾选即可同步到 `ref_asset_ids`
- 按角色分组表：`character -> emotion -> voice`，并显示该情绪下 ref 资产数量，支持一键回填 voice 表单
- synth 表单同步增加：`character/emotion/selection_policy/variation_seed/prefer_async/sync_wait_ms/use_instruction/instruction`

- “语音设置”页已改为 v2 单一数据源：默认读写 `app_config.json:v2_voices_config_path` 指向的 voices 文件，并支持“导入旧 config/config.json -> v2 voices + v2 assets”

落地文件：

## 2. 行为变化与兼容性说明

### 2.1 “同一输入输出一致”的实现方式
- 对 API v2：以“请求指纹 key”作为缓存键；同 key 永远返回同一份缓存音频（直到缓存被 LRU 淘汰或 voice 配置变更导致 key 变化）。
- 对桌面端：同样写入/读取 `data/cache`；但桌面端仍可能受随机 seed、run_count 版本号影响。当前实现把 `run_count+1` 作为 `variation_seed` 参与 voice 指纹，保证“不同版本”不会互相污染缓存。

### 2.2 voice 配置更新导致旧缓存失效
你要求“voice 配置改了旧缓存失效”。本次实现通过把以下内容纳入 key 来达成：
- voice 相关：mode、prompt_text（归一化）、instruct_text/ instruction（归一化）、prompt_audio 哈希、selected_ref_asset_id、variation_seed 等
- model 相关：model_dir、fp16、trt/vllm 开关（model_fingerprint）
- 请求相关：text 归一化、speed、part_index 等

只要这些字段变化，请求 key 就会变化，从而自然 miss（旧缓存不再命中）。

## 3. API v2：主要接口与新增字段（摘要）

### 3.1 `POST /api/v2/assets/audio`
新增可选 form 字段：
- `character`：角色名
- `emotion`：情绪标签（默认 `default`）
- `language`：语言标签（默认 `zh`）
- `note`：备注

### 3.2 `POST /api/v2/voices` / `PUT /api/v2/voices/<id>`
新增/强化字段：
- `character`、`emotion`
- `selection_policy`：`random_per_text`/`fixed`/`random_per_request`
- `ref_asset_ids`：参考音频资产 id 列表

同时支持 `name=角色#情绪` 时自动填充 `character/emotion`（若未显式提供）。

### 3.3 `POST /api/v2/synthesize`
新增（JSON 或 multipart）字段：
- `character`、`emotion`
- `selection_policy`、`variation_seed`
- `prefer_async`、`sync_wait_ms`
- `use_instruction`、`instruction`

响应头新增：
- `X-Cache: HIT|MISS`
- `X-Cache-Key: <hash>`

### 3.4 `POST /api/v2/jobs`
payload 增加可选字段：
- `priority`：数值越小越优先（默认 100）

## 4. 如何验证（最短路径）
1. 启动 API server（确保 `data/` 可写）。
2. 任选其一完成“上传 ref + 绑定 voice”：
   - 方式 A（桌面端）：打开 PyQt 的“情绪管理（v2）”，上传 ref（填写 `character/emotion`），再在 voice 上绑定 `ref_asset_ids`
   - 方式 B（网页端）：打开 `web_api_console.html`，上传 ref（`character=Tom`、`emotion=happy`），创建/更新 voice，并通过 Ref Picker 生成 `ref_asset_ids`
3. 合成同一句话两次：观察 `X-Cache` 从 `MISS` 变为 `HIT`；或在 JSON 模式查看 `cache.hit`。
4. 改 voice（例如替换 ref、改 prompt_text）：再合成应变成 `MISS`（旧缓存不命中）。

## 5. 已知限制/待处理项
- “独立 API 进程”（`StartAPIServer.bat`）与“桌面端内嵌 API”（`ui/api_page.py`）可能指向不同的 voices 文件：请确保 `--config` 与 `app_config.json:v2_voices_config_path` 指向同一个 JSON（否则会出现“UI 里能看到，API 里看不到”）。
- 如果你在外部编辑了 voices JSON 文件，可调用 `POST /api/v2/voices/reload` 让运行中的 API 重新加载。
- jobs 目前是单 worker 串行执行（更稳但吞吐有限）；后续可以做“可配置 worker 数量 + GPU/显存保护策略”。
- 缓存是 WAV 结果缓存，不包含“speaker embedding/spkinfo 的多情绪预编译资产化管理 UI”（compile 接口已支持 `?all=true`，但 UI 侧可继续完善）。

## 6. 下一步优化方案（建议顺序）

### 6.1 桌面端 UI：从“能用”到“顺手”（优先）
- 语音设置页与情绪管理页已经接入 v2，下一步建议优先补齐体验细节：
  - “语音设置”页：把 prompt_audio 全量迁移为 v2 assets（而不是本地路径），并提供一键修复/检查
  - “情绪管理”页：更强的筛选/搜索、批量 compile、批量删除/清理未引用 ref
  - 文本/任务页：统一用 v2 voices 列表（按 `character/emotion`）并默认走 v2 synth/jobs

### 6.2 统一配置模型（中优先）
目前已经确立 v2 voices 作为单一数据源，但仍有残留概念（例如 `voice_config_path` 作为旧配置导入入口）。
建议把“导入旧配置到 v2 / 导出备份 / 修复资产引用”做成一组明确入口，减少误用与配置漂移。

### 6.3 监控与可观测性增强（中优先）
- `/metrics` 增加：平均延迟、p95、推理耗时、合成耗时、cache 写入耗时、merge 耗时
- 增加日志字段：`cache_key`、`selected_ref_asset_id`、`character/emotion`

### 6.4 缓存与存储治理（中优先）
- 提供 cache 清理 API / UI（按 TTL、按总大小、按 voice、按最近访问）
- cache 统计：按 character/emotion 的占用分布

### 6.5 稳定性与测试（中优先）
- 增加最小集成测试脚本（本地跑一遍 assets->voice->synth->hit 的流程）
- 针对“多 ref + selection_policy + instruction + variation_seed”做回归测试
