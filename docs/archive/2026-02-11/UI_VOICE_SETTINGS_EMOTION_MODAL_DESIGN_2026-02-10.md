# 语音设置（v2）+ 情绪管理（v2）融合方案：将“情绪管理”做成语音设置的弹窗（Apple 风格）
最后更新：2026-02-10

目标：把“Voice 配方（v2 voices）”与“参考音频素材（v2 assets）”的管理合并成一条自然主线，减少页面割裂与误解；同时保留高级能力（批量、迁移、预编译）。

> 约束：仅写方案，不改代码。所有用户可见文本为中文。v2 数据结构为准：  
> - Voice（配方）：`voice_id = 角色#情绪`，核心字段 `mode/prompt_text/instruct_text/ref_asset_ids/selection_policy/...`  
> - Asset（素材）：SQLite 资产库（ref 音频），通过 `ref_asset_ids` 绑定到 voice

---

## 1. 设计判断：是否值得融合
结论：值得。原因：
- 你现在的主问题不是“功能缺失”，而是“用户心智被拆开”：一边在 voice 表格里填 prompt_audio/prompt_text；另一边在情绪页里上传 assets/绑定；用户会自然误以为“上传=可选”，或“这里改了那边不生效”。
- Apple 的做法通常是：**主任务一条线走完**，高级能力“按需展开”。把情绪页变成弹窗（sheet/drawer）能把主线闭环放在同一个上下文里：正在编辑哪个 voice，就在这里管理它的参考池。

同时建议保留一个“独立入口”（侧边栏的“情绪管理 v2”可以保留为高级入口），但默认路径从“语音设置”里进入弹窗。

---

## 2. 用户主线（你希望用户怎么用）
主线闭环（最短路径）：
1. 选择角色
2. 选择情绪（或创建新情绪）
3. 设置 voice 配方（模式、参考文本、选择策略等）
4. 管理参考音频池（上传、试听、绑定、设为主样本）
5. 预编译（可选）
6. 合成测试句（可选）

弹窗要服务“第 4 步”，并且让用户明确：**voice 负责引用资产池，资产池才是多参考音频的来源**。

---

## 3. 推荐信息架构（Apple 风格：清晰、克制、分层）
### 3.1 顶层页面：语音设置（升级为“角色与音色”）
把当前表格弱化为“批量视图”，默认用“列表 + 详情编辑”的结构：
- 左侧：角色列表（可搜索、收藏）
- 中间：情绪分段（default/happy/... + 自定义）
- 右侧：Voice 配方编辑卡片（固定布局，不随文本变化）
- 关键按钮：`管理参考音频…` 打开弹窗（sheet/drawer）

### 3.2 弹窗页面：参考音频库（情绪管理 v2，聚焦当前 voice）
弹窗必须明确“上下文”：
- 标题：`参考音频（胡桃 / calm）`
- 副标题：`参考池：3 条  |  选择策略：按文本随机（稳定）`
- 主区域：资产表格（ref assets）
- 主动作：上传、试听、加入参考池、设为主样本、删除
- 次动作：从 voice 解绑定、复制 asset_id、打开文件位置、compile（可选）

---

## 4. 多个推荐布局（ASCII 线框）
下面给 3 套布局，按“最像苹果且最容易落地”排序。

### 布局 A（推荐）：语音设置主界面 + 右侧弹出 Sheet（不离开上下文）
特点：用户仍停留在语音设置页，弹窗像 macOS 侧拉面板，最符合“克制”。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 角色与音色（v2）                         v2 配置：C:\...\super_agent.json       │
│ [搜索角色/情绪/voice_id]  [新建角色] [添加情绪] [预编译] [更多…]                │
├─────────────────┬─────────────────────────────────────────────┬──────────────┤
│ 角色列表         │ 情绪： [default|happy|sad|...| + ]          │ Voice 配方     │
│ - 胡桃           │                                             │ 模式：[零样本 ▾]│
│ - 夜兰           │ 参考池：3 条   [管理参考音频…]              │ 策略：[按文本随机▾]│
│ - …              │                                             │ 参考文本：      │
│                  │ 合成测试句：[输入框………………………][试听]     │ ┌────────────┐ │
│                  │                                             │ │多行，固定高│ │
│                  │                                             │ └────────────┘ │
│                  │                                             │ 指令文本(可选)：│
│                  │                                             │ ┌────────────┐ │
│                  │                                             │ │多行，固定高│ │
│                  │                                             │ └────────────┘ │
│                  │                                             │ [保存] [应用]  │
├──────────────────────────────────────────────────────────────────────────────┤
│ (右侧 Sheet 打开时覆盖右边 35-45% 宽度，不改变主布局)                           │
└──────────────────────────────────────────────────────────────────────────────┘

右侧 Sheet（“参考音频”弹窗）：
┌──────────────────────────────────────────────┐
│ 参考音频（胡桃 / calm）     参考池：3 条  [×] │
│ 情绪： [default|happy|...| + ]                │
│ 过滤：语音[zh ▾] 绑定[全部 ▾] 搜索[备注/ID…]  │
│ ┌──────────────────────────────────────────┐ │
│ │ 资产表格：名称 | 备注 | 时间 | 绑定 | id │ │
│ │ …                                          │
│ └──────────────────────────────────────────┘ │
│ [上传] [试听] [加入参考池] [设为主样本] [更多…] │
│ 提示：参考音频用于合成时从参考池中按策略选择 1 条│
└──────────────────────────────────────────────┘
```

适用场景：
- 你希望把“素材管理”作为“配方编辑”的一个子任务，而不是单独页面。

关键交互：
- `管理参考音频…`：打开 Sheet，默认定位到当前 `角色#情绪`。
- Sheet 中对资产的操作，立即反馈到主界面“参考池：N 条”与“主样本”等摘要。

### 布局 B：语音设置主界面 + 全屏弹窗（更像“资源库”，适合大量资产）
特点：当素材很多、需要更强筛选/批量操作时，全屏弹窗更舒服，也更像苹果的“媒体库”。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 角色与音色（v2）                                                             │
│ …（同布局 A 的主界面）…                                    [管理参考音频…]    │
└──────────────────────────────────────────────────────────────────────────────┘

点击后进入全屏弹窗（Modal）：
┌──────────────────────────────────────────────────────────────────────────────┐
│ 参考音频库（胡桃 / calm）                                      [完成] [取消]   │
│ 情绪： [default|happy|sad|...| + ]   参考池：3 条  策略：按文本随机（稳定）    │
│ 过滤：语音[zh ▾] 绑定[全部 ▾] 仅看当前 voice[□]  搜索[备注/文件名/asset_id]  │
├───────────────────────────────┬──────────────────────────────────────────────┤
│ 左侧：当前 voice 摘要          │ 右侧：资产表格（可多选）                      │
│ - 主样本：ref_xxx…            │ ┌──────────────────────────────────────────┐ │
│ - 最近使用：ref_yyy…          │ │ 名称 | 备注 | 时间 | 路径 | 绑定 | id     │ │
│ - 参考文本：…（只读预览）      │ │ …                                          │ │
│ [锁定主样本] [清空参考池]      │ └──────────────────────────────────────────┘ │
│                               │ [上传] [试听] [加入参考池] [解绑定] [删除]   │
└───────────────────────────────┴──────────────────────────────────────────────┘
```

适用场景：
- 你要管理大量 ref 音频（几十到几百），需要更强的信息密度。

关键交互：
- `完成`：写回 `ref_asset_ids`（或立即写回也可，但“完成/取消”更像苹果 sheet）。
- 支持批量：多选后“加入参考池/解绑定/删除”。

### 布局 C：把“情绪管理”收敛为“参考池编辑器”（最克制，但需要你接受功能拆分）
特点：弹窗只做“把资产加入/移出参考池”，其它资产元信息编辑（备注/情绪标签/语言）放在另一个“资源管理”入口里。

```text
主界面（语音设置）：
┌──────────────────────────────────────────────────────────────────────────────┐
│ …右侧 Voice 配方…  参考池：3 条  [编辑参考池…]                                │
└──────────────────────────────────────────────────────────────────────────────┘

弹窗（只编辑“参考池”）：
┌──────────────────────────────────────────────────────────────────────────────┐
│ 编辑参考池（胡桃 / calm）                                        [完成] [×]   │
│ 左：可用素材（同角色+同情绪）              右：已加入参考池（ref_asset_ids）     │
│ ┌──────────────────────────────────────┐ ┌──────────────────────────────────┐ │
│ │ 搜索素材…  过滤：语音[zh▾]           │ │ 主样本：ref_xxx… [设为主样本]     │ │
│ │ 素材列表（表格）                      │ │ 其余样本：ref_yyy…                │ │
│ │ [添加 →]                              │ │ [← 移除] [上移/下移]              │ │
│ └──────────────────────────────────────┘ └──────────────────────────────────┘ │
│ 提示：合成时会从右侧参考池中按策略选择 1 条（按文本随机可保持可复现与缓存命中） │
└──────────────────────────────────────────────────────────────────────────────┘
```

适用场景：
- 你希望极致清晰：这个弹窗只解决“这个 voice 用哪些参考”，不做素材库管理的“全能工具”。

代价：
- 需要另一个入口做“上传/删资产/改备注/改标签”等“资源管理”。

---

## 5. 方案建议：选哪一个
建议默认选择 **布局 A**：
- 最符合你当前项目“配方与素材分离但要在同一条主线闭环”的需求。
- 改动成本最低：可以保留现有情绪管理页的大部分控件与逻辑，只是呈现为弹窗，并且绑定上下文（当前 voice）。
- 用户不容易迷路：一直在同一页面完成“配方编辑”，弹窗只是“管理参考池”。

如果你未来 ref 资产数量很大，再考虑加一个“全屏弹窗模式”（布局 B）作为“展开”按钮。

---

## 6. 关键交互细节（必须统一，否则体验仍然割裂）
### 6.1 上下文锁定（核心）
弹窗打开时必须带上：
- 当前角色 `character`
- 当前情绪 `emotion`
- 当前 voice_id `character#emotion`

弹窗内的所有动作默认都对“当前 voice”生效（加入参考池、设为主样本、编译等）。

### 6.2 多参考音频与“主样本”的语义
建议给用户一个清晰约定（中文）：
- `主样本`：参考池里的第 1 条（用于 `固定主样本` 或作为优先展示/试听）
- `参考池`：其余条目，合成时按策略选择

UI 建议固定提供三档策略（中文）：
- `固定主样本（最稳定）`
- `按文本随机（稳定）`（默认，缓存友好）
- `每次随机（更丰富）`（高级选项，提示可能降低缓存命中）

### 6.3 预编译（compile）的呈现
建议把“预编译”作为主界面的高级动作，但在弹窗里也可以提供“仅编译当前 voice / 编译全部参考”的入口：
- 主界面：`预编译`（对当前 voice 或选中集合）
- 弹窗：`编译当前`、`编译全部参考`（仅针对当前 voice 的参考池）

### 6.4 反馈一致性（避免用户觉得“没生效”）
每个关键动作都要有即时反馈：
- 上传成功：提示“已加入素材库”
- 加入参考池：提示“已加入参考池（参考池：N 条）”
- 设为主样本：提示“已设为主样本”
- 编译：显示进度与结果（成功/失败数量）

---

## 7. 兼容保留：是否还需要侧边栏的“情绪管理(v2)”
建议保留，但改名与定位：
- 侧边栏：`参考音频库（高级）`（可选）
- 语音设置页：默认入口 `管理参考音频…`（主入口）

理由：Apple 也会保留“媒体库/偏好设置”的独立入口给高级用户，但不强迫普通用户理解所有概念。

---

## 8. 验收标准（融合成功的标志）
- 用户在“语音设置”里能完成闭环，不需要切换到侧边栏的情绪管理页也能把 voice 配好。
- 用户不会再误以为“上传=可选”，因为上传后立刻能看到“已加入参考池/参考池数量变化”。
- 声音库弹窗与情绪弹窗显示一致：一个展示 voices，一个展示当前 voice 的参考池，两者不会互相矛盾。
