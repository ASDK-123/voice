## 2. 当前阶段判断

## 2.1 实施计划阶段判断

### `P0` 主线冻结与边界确认

判断：**基本完成**

原因：

1. `ProWorkspace` 已被明确当作主工作站骨架推进。
2. README 与启动入口已经转为 WebUI-first。
3. 桌面 GUI 已在文档和脚本提示中被标记为 legacy / 回退入口。

剩余问题：

1. 仓库层面还没有完全做到“桌面端不再接新功能”，`ui/` 目录仍在发生改动。
2. 这说明 `P0-C` 在工程纪律层面还没彻底固化。

### `P1` API / Store 架构收敛

判断：**部分完成**

已完成：

1. 连接配置已经向统一来源收口。
2. WebUI 的鉴权音频处理已形成统一 blob/url 方案。
3. `Pro` 路线里的核心请求链已不再依赖本地假数据。

未完成：

1. `cosyvoice.ts` 与 `pro_client.ts` 仍然并存。
2. `pro_voice / pro_task` 与通用 `voices / project` 仍是双 store 模型。
3. “唯一权威 store” 这件事还没有彻底完成。

结论：

1. `P1` 已经够支撑业务推进。
2. 但从架构角度看，还没有完全收官。

### `P2` Voices + Assets 闭环

判断：**核心闭环已打通，边缘项未清**

已完成：

1. Voice 列表、创建、编辑、删除。
2. 情绪管理与角色分组。
3. compile 入口。
4. Assets 列表、上传、试听、绑定、解绑、删除。
5. note / transcript 编辑。
6. linked / unused 过滤。
7. 未引用资产清理流程。

未完成：

1. 批量改名还没有正式实现。
2. legacy 导入入口还没有进入 WebUI 正式流程。

结论：

1. `P2` 的高频业务闭环已经基本达标。
2. 但离“桌面 voice_settings.py 全量替代”还差少量高级入口。

### `P3` Workspace 生产闭环

判断：**主体已完成，仍需一轮稳定化**

已完成：

1. 脚本编辑与任务导入。
2. 行级参数控制。
3. 单行运行。
4. 批量运行。
5. 结果试听。
6. API Key 下播放修复。
7. 任务计划保存 / 加载 / 导入 / 导出。
8. 批量结果 merge 导出。

未完成或仍需验证：

1. 需要一轮真实后端回归，而不是只靠 mock smoke。
2. 任务工作流与正式 Export 模块的边界还未完全收口。
3. “结果列表回收” 体验上还有继续统一的空间。

结论：

1. `P3` 已经进入可用阶段。
2. 但还需要回归验证和模块整理，才能作为退场依据。

### `P4` System + Settings + Export 收口

判断：**已启动，未完成**

已完成：

1. health / model state / GPU/VRAM / unload / reload / cleanup 已有 WebUI 能力。
2. baseUrl / apiKey / 当前连接配置已在 Web 端可配。
3. Export 相关能力在旧 `ExportPanel` 与 `ProWorkspace` 中都有部分实现。

3. System 与 Settings 还没有成为清晰的正式一级模块。

未完成：

## 2.2 退场阶段判断

结论：**仍处于 `G0`，但已经接近 `G1`**

3. 但仍缺一轮“真实 API、API Key 开/关、真实后端数据”的成体系回归。

## 4. 当前仍存在的关键缺口

1. API 客户端仍是双轨：
   - `cosyvoice.ts`
   - `pro_client.ts`
2. Store 仍是双轨：
   - `pro_voice / pro_task`
   - `voices / project`

2. System / Settings 还没有真正作为正式一级模块定型。
3. App Shell 仍保留大量历史 tab，产品结构尚未收敛。

## 4.3 退场层缺口

1. 还没有完成一轮真实后端回归签收。
2. 还没有建立足够覆盖 `G2-Q1` 的回归清单。
3. 桌面 GUI 虽然已被标记 legacy，但工程上还没真正冻结。

## 5. 下一步应该做什么

结论：

> 下一步不应该再优先做视觉整理，也不应该急着删桌面 GUI。  
> 应该进入 `P4`，并同时补一轮“退场门槛验证”。

建议开发顺序如下。

### 第一优先级：完成 `P4 Export / System / Settings` 收口

应先做：

1. 让 Export 成为正式模块，而不是零散能力集合。
2. 明确 `ProWorkspace` 与 `ExportPanel` 的关系：
   - 哪些导出留在 Workspace
   - 哪些归到 Export 正式页
3. 把工程导入导出、音频导出、SRT 导出整理成稳定入口。
4. 把连接配置、System 状态、模型控制整理成正式 System / Settings 模块。

原因：

1. 这是进入 `G1/G2` 前最后一个明显的产品级空洞。

### 第二优先级：做一轮真实后端回归签收

建议覆盖：

1. 无 API Key 主流程
2. 有 API Key 主流程
3. Voice 创建/编辑/删除
4. Asset 上传/试听/绑定/解绑/清理
5. 批量合成
6. 单行运行
7. 任务保存/加载
8. merge 导出

原因：

1. 当前 smoke 是必要基础，但还不足以替代真实后端验收。

### 第三优先级：推进 `P5 App Shell` 重建

应做：

1. 正式导航改造成：
   - Workspace
   - Voices
   - Assets
   - Library
   - Export
   - System
2. 明确哪些旧 tab 继续保留为过渡入口，哪些直接退役。
3. 把 legacy 页从默认路径中撤掉。

原因：

1. 当前虽然默认进入 WebUI 主线，但信息架构仍是混合态。

### 第四优先级：回头补 `P1` 未完成的架构收敛

应做：

1. 合并 API client 分层。
2. 确定 voice / task / system 的唯一权威 store。

原因：

1. 这是“业务闭环之后”的正确重构时机。
2. 现在回头做，风险比早期小得多。
