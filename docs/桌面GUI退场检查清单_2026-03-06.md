## 1. 文档目的

本文用于回答一个非常具体的问题：

> 到什么程度，才可以默认切换到 WebUI，并让桌面 GUI 进入冻结、观察和最终退场？

这不是功能愿景文档，而是一份门禁清单。

只有当下面的关键条件满足后，桌面 GUI 才能进入下一阶段退场。

---

## 2. 退场阶段定义

建议把退场分为四个阶段：

1. `G0` 并行阶段
2. `G1` 默认推荐 WebUI
3. `G2` 桌面 GUI 冻结
4. `G3` 桌面 GUI 退出主线

## 2.1 G0：并行阶段

定义：

1. WebUI 仍未形成完整替代能力。
2. 桌面 GUI 继续承担主工作流。

现状判断：

1. 当前项目仍处于 `G0`。

## 2.2 G1：默认推荐 WebUI

定义：

1. WebUI 已能完成核心工作流。
2. 桌面 GUI 仍可作为备用入口。

用户层表现：

1. README 与使用文档开始优先介绍 WebUI。
2. 新用户默认走 WebUI。

## 2.3 G2：桌面 GUI 冻结

定义：

1. 不再接受桌面 GUI 新功能。
2. 桌面 GUI 仅做严重 bug 修复。

用户层表现：

1. 桌面 GUI 被明确标记为 legacy / maintenance mode。

## 2.4 G3：桌面 GUI 退出主线

定义：

1. 默认启动方式改为 WebUI。
2. 桌面 GUI 不再作为正式产品前端维护。

可能保留：

1. 历史分支
2. 特殊环境下的临时兼容入口

---

## 3. 总门槛原则

桌面 GUI 不能因为“WebUI 看起来能用了”就退场。

必须同时满足三类条件：

1. `功能替代`
2. `质量可控`
3. `文档与迁移可执行`

少任何一类，都不应推进到下一阶段。

---

## 4. G1 门槛：默认推荐 WebUI

只有满足下面所有 `G1 必过项`，才能进入“默认推荐 WebUI”。

## 4.1 功能替代门槛

### G1-F1 Workspace 主流程成立

必须满足：

1. WebUI 能完成剧本编辑。
2. WebUI 能完成任务计划编辑。
3. WebUI 能完成批量合成。
4. WebUI 能完成结果试听。

验收方式：

1. 从空项目开始，在 WebUI 内完成一轮完整文本到音频流程。

### G1-F2 Voices 主流程成立

必须满足：

1. 能列出 voices。
2. 能创建 voice。
3. 能编辑 voice。
4. 能删除 voice。
5. 数据刷新后保持一致。

### G1-F3 Assets 主流程成立

必须满足：

1. 能上传参考音频。
2. 能试听参考音频。
3. 能绑定/解绑到 voice。
4. 能删除资产。
5. 能看到资产列表和基础过滤。

### G1-F4 System 主流程成立

必须满足：

1. WebUI 可显示健康状态。
2. WebUI 可显示模型是否加载。
3. WebUI 可执行 unload/reload。
4. WebUI 可配置后端连接。

## 4.2 质量门槛

### G1-Q1 鉴权场景可用

必须满足：

1. 关闭 API Key 可正常工作。
2. 开启 API Key 仍可正常：
   - 拉列表
   - 合成
   - 播放结果音频
   - 拉资产内容

### G1-Q2 核心错误反馈完整

必须满足：

1. 网络错误有可见反馈。
2. 表单校验错误有可见反馈。
3. 合成失败有可见反馈。
4. 上传失败有可见反馈。

### G1-Q3 无致命功能回归

必须满足：

1. 经手工回归验证，WebUI 不存在阻断主流程的高概率问题。

## 4.3 文档门槛

### G1-D1 用户文档可用

必须满足：

1. README 中有 WebUI 启动与使用说明。
2. 已有从桌面 GUI 切换到 WebUI 的基本说明。

### G1-D2 团队内部边界清楚

必须满足：

1. 团队明确桌面 GUI 不再作为新功能主线。

---

## 5. G2 门槛：桌面 GUI 冻结

只有满足下面所有 `G2 必过项`，桌面 GUI 才能进入冻结态。

## 5.1 功能覆盖门槛

### G2-F1 Voices + Assets 闭环完整

必须满足：

1. 情绪管理是真实业务闭环，不是占位 UI。
2. 参考音频上传、试听、绑定、解绑、备注、清理全部在 Web 可完成。
3. 桌面 `voice_settings.py` 的高频工作流在 Web 可替代。

### G2-F2 Workspace 高级参数补齐

必须满足：

1. 支持 `mode`
2. 支持 `instruct_text`
3. 支持 `seed`
4. 支持单行运行
5. 支持任务计划保存/加载
6. 支持 merge 或等价结果导出路径

### G2-F3 Export 正式可用

必须满足：

1. 工程导入/导出稳定
2. 音频导出稳定
3. 字幕导出稳定

## 5.2 质量门槛

### G2-Q1 回归用例稳定

至少应覆盖：

1. 新建 voice
2. 上传 asset
3. 绑定 asset
4. 批量合成
5. 导出工程
6. 导出音频
7. 有鉴权播放

### G2-Q2 基础自动化存在

至少需要：

1. 一组最小 E2E 或 smoke 检查
2. 覆盖 WebUI 主工作流

说明：

没有任何自动化时，不建议冻结桌面 GUI。

## 5.3 产品门槛

### G2-P1 WebUI 成为默认入口

必须满足：

1. 启动说明默认介绍 WebUI。
2. WebUI 是默认推荐入口。
3. 桌面 GUI 明确标注为 legacy。

---

## 6. G3 门槛：桌面 GUI 退出主线

只有满足下面所有 `G3 必过项`，桌面 GUI 才能退出主线。

## 6.1 运行门槛

### G3-R1 WebUI 可独立承担正式使用

必须满足：

1. 新用户无需打开桌面 GUI。
2. 老用户高频任务可完全迁移到 WebUI。

### G3-R2 桌面专属能力已处理

必须满足下列三种处理之一：

1. 已迁移
2. 已重构替代
3. 已明确放弃并完成文档说明

不能出现：

1. 某些关键场景还必须打开桌面 GUI，但没有记录。

## 6.2 观察期门槛

### G3-O1 至少完成一段观察期

建议观察期：

1. 1 到 2 个迭代周期

观察目标：

1. 主流程问题是否继续集中爆发
2. 用户是否频繁回退到桌面 GUI

### G3-O2 无阻断性回退理由

如果仍存在以下情况，则不能退出主线：

1. voice/asset 管理仍需桌面补救
2. 有鉴权场景下 WebUI 仍不稳定
3. 批量结果回收仍依赖桌面
4. 系统连接/模型控制仍需桌面

## 6.3 文档门槛

### G3-D1 已有退场说明

必须满足：

1. README 明确写明桌面 GUI 的地位。
2. 迁移说明文档已存在。
3. 已有遗留能力处理说明。

### G3-D2 已有维护策略说明

必须满足：

1. 明确桌面 GUI 是否保留最低限度维护。
2. 明确哪些情况仍会修复桌面问题。

## 8. 阶段推进决策表

## 是否可以进入 G1：默认推荐 WebUI

必须全部为“是”：

1. Voices 主流程已完成？
2. Assets 基础主流程已完成？
3. Workspace 批量主流程已完成？
4. System 基础控制已完成？
5. 鉴权场景可用？
6. 用户文档已准备？

若有任一项为“否”：

1. 不能进入 G1。

## 是否可以进入 G2：桌面 GUI 冻结

必须全部为“是”：

1. Voices + Assets 闭环完整？
2. Workspace 高级参数补齐？
3. Export 正式可用？
4. 有基础自动化？
5. WebUI 已是默认入口？

若有任一项为“否”：

1. 不能进入 G2。

## 是否可以进入 G3：桌面 GUI 退出主线

必须全部为“是”：

1. WebUI 已独立承担正式使用？
2. 桌面专属关键能力已处理？
3. 已完成观察期？
4. 无阻断性回退理由？
5. 退场说明与维护策略已写清楚？

若有任一项为“否”：

1. 不能进入 G3。

## 9. 退场执行建议

## 9.1 进入 G1 时

建议动作：

1. README 默认放 WebUI 启动方式。
2. 桌面 GUI 保留，但不再作为首推入口。

## 9.2 进入 G2 时

建议动作：

1. 桌面 GUI 显示 legacy 提示。
2. 桌面 GUI 不再接收新功能需求。
3. 默认开发资源转向 WebUI。

## 9.3 进入 G3 时

建议动作：

1. 默认启动脚本切换为 WebUI。
2. 桌面 GUI 从主文档中降级为兼容方案。
3. 桌面 GUI 停止主线维护。
