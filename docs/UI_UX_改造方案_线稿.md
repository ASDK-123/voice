# CosyVoice Desktop UI/UX 改造方案（基于 `ui-ux-pro-max`）

> 适用范围：`ui/` 目录下的 PyQt5 + qfluentwidgets 桌面界面
> 
> 方案来源：`ui-ux-pro-max` 的 `--design-system`、`--domain ux/color/typography` 输出 + 当前代码结构审查

## 1. 方法与结论摘要

本方案按照 `ui-ux-pro-max` 推荐流程执行：
1. 生成 Design System（整体视觉方向）
2. 补充 UX/A11y 规则（可用性与状态反馈）
3. 映射到当前 PyQt 页面结构，形成“可直接开工”的按文件改造清单

关键结论：
- 视觉方向建议采用 **Flat Design（扁平、清晰、弱装饰）**，这与当前工具型桌面应用定位一致。
- 当前代码已存在 token 基础（`ui/theme/tokens.py`），但跨页面统一不足，尤其在 `api_page.py`、`emotion_voices.py`。
- 优先级最高的改造点：
  - 去 Emoji 化（标题/按钮/日志状态表达）
  - 统一颜色与文字对比（减少硬编码 `gray/rgba`）
  - 统一状态反馈与加载反馈（按钮 busy、表格刷新/空态）
  - 减少僵硬固定尺寸，提升窗口变化下的可读性

## 3. 目标与设计原则

## 3.1 业务目标

1. 降低新用户理解成本（信息层级更清晰）
2. 提升高频流程效率（语音配置、情绪音频管理、API 运维）
3. 减少视觉噪音（统一风格、统一图标语义）

## 3.2 UX/A11y 原则（从 skill 落地）

1. 可见焦点：所有可交互控件有明确 focus 样式
2. 对比达标：正文/说明文字达到可读对比（目标 >= 4.5:1）
3. 统一反馈：超过 300ms 操作必须有 loading 指示
4. 防误触：异步按钮在进行中禁用，避免重复提交
5. 状态一致：成功/警告/错误使用统一色阶与文本模板

## 4. 视觉系统提案（Desktop 适配版）

> 注：`ui-ux-pro-max` 给出的主色倾向（teal/blue）可用，但桌面工具应优先“稳态可读”。

## 4.1 色彩建议（在现有 tokens 基础上升级）

- 保留中性背景体系（适合工具软件）
- 引入单一强调色（建议蓝青）用于主按钮和焦点态
- 语义色保持三类：成功/警告/错误

建议扩展 `Palette`：
- `ACCENT = #0369A1`
- `ACCENT_HOVER = #075985`
- `FOCUS_RING = #0EA5E9`
- `TEXT_MUTED = #64748B`（替代分散的 `gray`、`rgba`）

## 4.2 字体建议

- 中文场景优先：`Noto Sans SC` 或系统中文无衬线
- 数字/日志：`Consolas`/`Fira Code`（仅日志区）

## 4.3 间距与圆角

- 继续使用 `Spacing/Radius/Metrics`，禁止新页面硬编码间距
- 统一卡片圆角与表格行高，减少页面割裂感

## 5. 页面级详细改造方案

## 5.1 `ui/main_window.py`（应用壳层）

修改项：
1. 侧栏文案统一（去 Emoji，统一命名风格：动词+对象）
2. 统一底部快捷入口视觉权重（加载/卸载模型/主题切换）
3. 增加“当前模型状态 + API状态”轻量状态条（可选）

验收标准：
- 导航项风格一致，无 Emoji
- 状态信息可一眼识别，不进入子页也能知道模型/API是否在线

## 5.2 `ui/voice_settings.py`（主基线页）

修改项：
1. 将当前样式系统抽离为可复用 helper（供其他页面复用）
2. 统一按钮层级：Primary（应用/保存）Secondary（加载/工具）
3. 表格列优先级调整：角色/情绪、模式、主参考优先可见
4. 编辑模式与浏览模式视觉分离（顶部条显式显示当前模式）

验收标准：
- 作为设计基线页可复用到 `emotion_voices/api_page`
- 复杂表格在 1280 宽度下不出现关键字段遮挡

## 5.3 `ui/emotion_voices.py`（重点改造页）

修改项：
1. 左右双栏重构为“配置区 + 资源区”明确主次
2. 将高频按钮聚合为操作组（保存/编译/绑定），次要动作放二级菜单
3. 减少固定宽高：
   - Host/Port 使用最小宽度 + stretch
   - 文本框高度改为 min/max，支持窗口变化
4. 参考音频表头增加状态标签（已绑定/未绑定）色块一致化
5. 上传流程反馈统一：选择文件 -> 上传中 -> 成功/失败

验收标准：
- 1440/1280/1024 下布局不破碎
- 高频操作路径不超过 2 次点击
- 资源选择和 voice 绑定关系更清晰

## 5.4 `ui/api_page.py`（第二重点）

修改项：
1. 标题、按钮、日志状态全面去 Emoji（改为 FluentIcon + 文本）
2. 控制区重排为：服务控制 > 运行开关 > 角色列表
3. 日志区引入级别徽标（INFO/WARN/ERROR/SUCCESS）而不是 Emoji 颜色猜测
4. 启停按钮加入 busy 态（启动中/停止中禁用重复点击）
5. API 与桥接状态卡片化展示（在线/离线 + 端口 + 最近错误摘要）

验收标准：
- 视觉风格与 VoiceSettings 一致
- 启停过程无重复触发、无“无反馈等待”

## 5.5 `ui/text_edit.py` / `ui/task_plan.py`

修改项：
1. 标题文案去 Emoji
2. 表格行动按钮统一尺寸与对齐
3. 日志/状态信息改为统一前缀模板（如 `[成功]`、`[失败]`）

验收标准：
- 同一类动作按钮在两页尺寸与样式一致
- 日志无需依赖彩色 emoji 即可读

## 5.6 `ui/settings.py` / `ui/voice_setup_wizard.py` / `ui/asset_cleanup_dialog.py`

修改项：
1. 替换硬编码 `gray`、`rgba(0,0,0,0.65)` 为 token
2. 向导页状态文字颜色统一为语义 token（secondary/success/warn/error）
3. 说明文字字号和行高统一

验收标准：
- 浅色/深色主题下说明文字均可读
- 同类提示信息颜色语义一致

## 6. 组件级规范（建议新增）

建议在 `ui/components/` 增加统一能力：
1. `status_badge.py`：统一状态标签（在线/离线/成功/失败）
2. `async_button.py`：统一加载态按钮（busy text + spinner + disable）
3. `page_header.py`：标题+副标题+右侧操作区
4. `empty_state.py`：空列表、加载失败、无结果统一展示

收益：
- 减少重复 `setStyleSheet` 与碎片化逻辑
- 新页面可快速套用一致 UI

## 9. 验收清单

1. 无 Emoji 作为 UI 图标语义（保留日志原文除外）
2. 关键异步按钮具备 loading + 禁用机制
3. 所有说明文字来自 token，不使用硬编码灰色
4. `voice_settings`、`emotion_voices`、`api_page` 风格一致
5. 窗口宽度 1024 以上无关键控件遮挡
6. 明暗主题下文字可读性稳定
