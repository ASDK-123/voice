# TTS 模型复用与后端打包分析（2026-03-03）

## 1. 结论（先说结果）

这个项目的 TTS 能力可以在其它语音合成项目中使用，推荐两种方式：

1. 作为独立 HTTP 服务复用（最稳，改造成本最低）  
   直接启动 `core/api.py`（可选再启动 `bridge.py`），外部项目走 HTTP 调用。
2. 作为 Python 模块内嵌复用（灵活，但耦合更高）  
   直接 import `cosyvoice.cli.cosyvoice.AutoModel`，在你的项目里调用 `inference_zero_shot / inference_instruct2 / inference_cross_lingual`。

从当前代码看，后端不是“只包了 API 壳”，而是本地加载 CosyVoice3 模型推理。关键加载点：

- `core/utils.py:7` `load_cosyvoice_model()`
- `core/utils.py:46` `AutoModel(...)`
- `core/api_legacy.py:31` 将 `third_party/Matcha-TTS` 加入 `sys.path`
- `core/api_legacy.py:428-444` 初始化 `data/`、SQLite 资产库等运行时目录

## 2. 能否跨项目使用：边界说明

### 2.1 可以复用的核心

- 推理引擎：`cosyvoice/`
- 模型权重：`pretrained_models/Fun-CosyVoice3-0.5B/`
- 文本归一化模型：`pretrained_models/wetext/`
- 后端 API：`core/`（v1 + v2）

### 2.2 需要注意的现实约束

1. 许可证  
   本仓库代码许可证是 Apache 2.0（`LICENSE`，`README.md` 也声明）。  
   但模型权重仍建议以模型卡/上游仓库条款为准（尤其是商用场景）。
2. 路径可移植性  
   当前 `app_config.json`、`config/super_agent.json` 含大量绝对路径（如 `C:\Users\lilei\Desktop\voice\...`）。迁移后必须改成新机器可用路径（建议改相对路径）。
3. 运行时环境  
   仓库没有标准根目录 `requirements.txt`（仅 `deprecated/bridge_requirements.txt`），因此“可直接运行”的包应包含现成 Python 运行环境（例如 `.pixi/envs/default`）或自行补齐依赖安装方案。

## 3. 你应该打包哪些文件（可直接跑后端）

下面按“最小可运行”和“完整可迁移”两档给清单。

## 3.1 最小可运行后端包（仅保留 TTS API 能力）

必带：

- `core/`
- `cosyvoice/`
- `third_party/Matcha-TTS/`
- `pretrained_models/Fun-CosyVoice3-0.5B/`
- `pretrained_models/wetext/`
- `app_config.json`
- `core/api.py`
- （运行环境二选一）
  - 方案 A：`.pixi/envs/default/`（你现在就是这么启动）
  - 方案 B：你自己准备的 Python venv + 完整依赖

建议带：

- `StartAPIServer.bat`（Windows 一键启动）
- `bridge.py`（如果你需要 OpenAI 兼容 `/v1/audio/speech`）
- `LICENSE`

可不带（不影响 API 推理本体）：

- `ui/`、`web_ui/`、`client/`、`tests/`、`docs/`、`main.py`

## 3.2 完整可迁移后端包（含现有 voice 库/资产）

在 3.1 基础上再加：

- `config/super_agent.json`（或你实际用的 voices 配置）
- `data/assets/audio/`（参考音频文件）
- `data/api_v2_assets.sqlite3`（v2 资产索引）
- `data/cache/`（可选，带缓存可减少首次重复生成）
- `data/logs/`（可选，带历史日志）

如果不带这些，服务仍可启动，但你原有角色与资产绑定关系会丢失。

## 4. 推荐的可复用方式

## 4.1 推荐：把它当“模型后端微服务”

启动命令（项目里已有）：

```bash
.pixi\envs\default\python.exe core\api.py --config config\super_agent.json --host 0.0.0.0 --port 9880
```

你的其它项目直接请求：

- `POST /api/v2/synthesize`（主接口）
- `POST /api/tts_direct`（不依赖 voice 配置，直接传参考音频）
- 可选 `POST /v1/audio/speech`（通过 `bridge.py` 兼容 OpenAI 风格）

## 4.2 内嵌调用（不走 HTTP）

可直接 import `AutoModel`，但你要自己处理：

- 文本预处理
- 并发与缓存
- 资产管理
- 接口层协议

对工程成本而言，一般不如直接复用现成 API 服务。

## 5. 打包前必须处理的 4 个坑

1. 把绝对路径改掉  
   `app_config.json` 和 `config/super_agent.json` 中的 `C:\...` 必须替换。
2. 确保工作目录正确  
   部分逻辑用相对路径（如 `pretrained_models/wetext`），建议固定从项目根目录启动。
3. FFmpeg  
   变速/合并相关功能依赖系统 `ffmpeg`（不装也可跑基础合成，但相关接口会受影响）。
4. 模型文件完整性  
   `Fun-CosyVoice3-0.5B` 目录必须完整（`cosyvoice3.yaml`、`llm.pt`、`flow.pt`、`hift.pt`、`speech_tokenizer_v3.onnx` 等）。

## 6. 一句话建议

如果目标是“在其它项目快速稳定接入”，最优策略是：  
**把当前仓库裁剪成后端包（3.1/3.2），以 HTTP 服务方式提供 TTS，业务项目通过 API 调用，而不是二次重写推理层。**
